# 設計の基本方針と決定事項

## 1. コンセプト

- **スマホ・タブレット（かんたんモード）**：撮った写真を3ステップでPDFに。「撮る/選ぶ → 確認・補正 → 保存/送る」
- **PC（詳細モード）**：結合・ページ整理・分割などの主要機能
- **共通**：ブラウザ内で完結する（ファイルを外部に送らない）。単一HTMLのPWAで、オフラインでも動く。一般公開できる構成にする

## 2. 設計原則

1. **ページリスト方式**
   読み込んだPDF・画像をすべて「ページの並び」として扱う。各ページは「元データ・回転・補正情報」を持つ。結合・並べ替え・削除・抽出・写真のPDF化を、すべて同じ仕組みで扱う。仕様は [page-list.md](page-list.md) を参照。
2. **Core層とUI層を分ける**
   ページリストの操作やPDF生成はCore（`src/core/`）、画面はUI（`index.html` と `src/app/`）が担当する。CoreはDOMやブラウザ専用のAPIに触らず、Node.jsでテストできるようにする。画像の読み込みやPDFの表示など、ブラウザが必要な部品は `src/web/` に置く。
3. **状態は変更せず、新しく作る**
   Coreの操作は元の状態を書き換えず、新しい状態を返す。こうしておくと「元に戻す」機能や自動保存を作りやすい。
4. **状態とファイルの中身を分ける**
   ページリストはJSONに変換できる情報だけを持つ。PDFや写真の中身（バイナリ）は `sourceId` をキーにして別の場所（メモリやIndexedDB）に置く。
5. **重い処理は必要になったときだけ読み込む**
   自動四隅検出、日本語フォント、OCRなどは、その機能を使う画面を開いたときに読み込む。一度読み込んだらキャッシュし、オフラインでも使えるようにする。
6. **メモリを節約する**
   大きな写真は読み込むときに縮小し、1枚ずつ処理する（iPhoneのメモリ対策）。
7. **モード切替**
   画面の幅とタッチ端末かどうかで自動判定し、手動でも切り替えられるようにする。

## 3. 決定事項

| 項目 | 決定 | 理由・補足 |
|---|---|---|
| アプリ名 | **RelaPDF** | RelaVas・Relamemoとシリーズで名前をそろえる。「PDF」はISO規格の名前なので使ってよい |
| ライセンス | **MIT** | 誰でも自由に使えるが、作者名とライセンス文を残すことが条件。無保証 |
| ファイル構成 | `index.html`（画面の骨組みとCSS）を本体とし、JavaScript（`src/`）・`sw.js`・manifest・アイコン・`vendor/`（ライブラリ）は別ファイル | Service Workerは別ファイルにしかできない。ライブラリを全部埋め込むと最初の読み込みが重くなる。JavaScriptをHTMLに直接書くとCSPで `unsafe-inline` を許す必要があるため、別ファイルにした |
| ビルド | **なし**（ファイルをそのまま公開） | 構成を単純に保つ。CoreはES Modulesで書き、ブラウザとNodeの両方から読み込む |
| テスト | Core：Node標準の `node:test`（`npm test`）。画面：Playwright（`npm run test:e2e`） | 開発用のパッケージは Playwright だけ |
| オフライン対応 | `sw.js` がアプリの全ファイルを最初にキャッシュする。一覧とバージョンは `scripts/precache.js` が作る `precache-manifest.js` | ファイルを変えたら `npm run precache`。古いままだと `npm test` が失敗して知らせる |
| 保存・共有 | PDFを作り終えてから「送る・保存する」「ダウンロード」ボタンを出す。終わったら「完了しました」「保存しました」を表示し、「新しく作る」を選べる | iPhoneの共有シートは、ボタンを押した直後でないと開けないため。共有シートをキャンセルしたときは何も表示せず、選び直せるようにする |
| かんたんモードの流れ | 「1 撮る・選ぶ → 2 確認 → 3 保存」の3ステップ。画面上部の①②③を押すと、その段階にすぐ移れる（写真がないときは②③は押せない） | ①に戻っても写真は残る（「いま○ページあります。撮った写真は後ろに追加されます」）。段階を移るボタンで写真が消えることはない。どの段階にいる状態も自動保存して再開する |
| 最初からやり直す | ①（写真があるとき）と③に「最初からやり直す（すべて削除）」、②に「すべて削除」。押すとすぐ①に戻り、6秒間「すべて削除しました［元に戻す］」を出す。保存後の「新しく作る」も同じ | 確認ダイアログより素早くやり直せて、押し間違えても取り戻せる。端末に保存した写真は6秒たってから消す |
| スマホの「戻る」操作 | Android の戻るボタンや iPhone の左端からのスワイプで ③→②→① と戻れる（ブラウザの履歴を使う）。カメラ・補正画面・ダイアログが開いていれば、まずそれを閉じる | ホーム画面から開いたアプリにはブラウザの戻るボタンがないため。履歴の最初に「番兵」を置き、①でカメラを開いているときの「戻る」でアプリが閉じないようにしている |
| カメラの取り消し | 撮影中、最後の1枚の小さな写真（×の印）を押すと取り消せる。続けて押せば、さらに前の1枚も取り消せる | 「失敗した」と感じるのは撮った直後の1枚が多いため |
| 4点補正 | 写真のサムネイルをタップするか「4点補正」ボタンで補正画面を開く。四隅と辺の中点の丸、ドラッグ中のルーペ（3倍）、A4比率。四隅は写真の外にも25%まで動かせる（はみ出した部分は白）。補正しないのが初期値（M5の自動検出で初期位置を賢くする） | 四隅は「写真の回転情報を反映したあと、ユーザーの回転をかける前」の写真に対する0〜1の割合で保存する（[page-list.md](page-list.md)）。画面ではページの回転をかけた向きで表示する |
| 並べ替え | スマホは各ページの「つまみ」を押さえてドラッグ。PCはページの絵をマウスでドラッグ（前後への移動ボタンも残す） | ページ全体をドラッグ可能にすると、スマホで一覧をスクロールしにくくなるため |
| ライブラリの置き場所 | **リポジトリに同梱** | オフラインで動かすため。CDNは使わない |
| 公開先 | **Vercel**（GitHubリポジトリと連携して自動で公開） | アクセス数を見るため |
| アクセス解析 | **Vercel Web Analytics**（アクセス数がわかる程度） | Cookieを使わない。ファイルの中身は送らない |
| 外部との通信 | アクセス解析以外は行わない。CSPで制限する | Vercelのアクセス解析は同じドメインの `/_vercel/insights/` を使う |
| 対象端末 | iPhone（iOS 17以上）、Android（Chrome）、PC（Chrome/Edgeが中心、Safariも最低限動く） | 最新のPDF.jsは新しめのSafariを前提にしている |
| Androidの確認 | Playwrightで端末の画面サイズやタッチ操作を再現してテストする。公開前に可能なら実機で確認する | 開発者がAndroid端末を持っていない |
| カメラの明るさ | 撮影画面のスライダーで50%〜200%。プレビューと撮った写真の両方に同じ倍率をかける。設定は覚えておく | iPhoneのSafariはカメラの露出調整に対応していないため、写真の色に倍率をかける方式にした |
| カメラ撮影 | **アプリ内カメラで連続撮影**（`getUserMedia`、背面カメラ、できるだけ高解像度）。シャッターのたびに映像の1コマを写真にする。「端末のカメラアプリで撮る」も用意する | OSのカメラは画質が良い。カメラの許可を拒否されたときの代わりにもなる。ほかのアプリに切り替えたらカメラを止める |
| 向きの自動補正 | 写真の回転情報（EXIF）と、撮影したときの端末の向きに合わせる程度 | 書類の中身から向きを判定することはしない。アプリ内カメラは、画面の向きが固定されていなければ映像が端末の向きに合わせて回るので、その向きで撮れる。画面の向きを固定しているときは、確認画面で回転してもらう |
| 写真をPDFにするときの用紙 | 初期値は**A4**（縦横は写真に合わせて自動）。「写真のサイズのまま」も選べる | |
| 圧縮の目安 | 標準：A4で約150dpi相当／高画質：約300dpi相当 | |
| 作業途中の保存 | 作業中のページリスト・ファイル名・設定・段階を端末内（IndexedDB、データベース名 `relapdf`）に自動保存し、再読み込みされても再開できる。履歴は持たない。「新しく作る」「すべて削除」で消す | iPhoneはカメラから戻ったときにページを再読み込みすることがある。元データの中身を先に保存してからページリストを保存するので、途中で閉じても壊れない |
| UIの言語 | 日本語 | |
| 自動アップデート | 起動時・アプリに戻ったとき（10分以上あけて）・1時間ごとに新しいバージョンを確かめ、見つかれば裏で全ファイルを取り込む。作業中でなければすぐ切り替え、作業中なら「新しいバージョンがあります［更新する］」を出す。ほかのアプリに切り替えている間は自動で切り替える。カメラ・補正画面・ダイアログ・処理中は切り替えない | 切り替えるときは作業を保存してから読み込み直すので、続きから再開できる。切り替わったら「最新版（vX）に更新しました」と表示する |
| ホーム画面への追加 | Android・PC の Chrome/Edge はアプリのボタンからインストール画面を出す。iPhone/iPad は「共有ボタン →ホーム画面に追加」の手順を案内する。ホーム画面から開いているときは案内を出さない | iPhone は、アプリからインストール画面を出す仕組みがないため |
| バージョン表示 | 画面右下に「RelaPDF v0.2.0」の形で表示する。値は `src/app/version.js` と `package.json` の両方に書く（違うとテストが失敗する） | 0.x は公開前（M2＝0.2.0、M3＝0.3.0 …）、M8で公開するときに 1.0.0 にする。下のバーが出ているときは、その上に表示する |
| ドキュメントとコメント | `docs/` に置く。コードのコメントは日本語 | リラメモの書き方にそろえる（未確認。[handover.md](handover.md) 参照） |
| リラメモ連携 | **今は作らない**。[roadmap.md](roadmap.md) の「今後の課題」に記録 | |

## 4. 使うライブラリ

MIT・Apache・OFL系に限り、AGPL系は使わない。どれもリポジトリの `vendor/` に同梱する（詳細は `vendor/README.md`）。

| ライブラリ | 用途 | ライセンス | 使い始め |
|---|---|---|---|
| pdf-lib 1.17.1 | PDFの生成・編集 | MIT | M1 |
| PDF.js 6.4.299（legacy版） | PDFの表示・画像化 | Apache 2.0 | M1 |
| fflate | 複数の画像をZIPにまとめる | MIT | M4 |
| OpenCV.js（または自作の軽い処理） | 四隅の自動検出 | Apache 2.0 | M5 |
| Noto Sans JP | 日本語フォント | OFL | M6 |
| qpdf（WASM版）など | パスワードの設定・解除 | Apache 2.0 | M7 |
| Tesseract.js | OCR | Apache 2.0 | M7 |

## 5. 注意しておく制約

- **pdf-libは暗号化に対応していない**：パスワード付きPDFは読み込めない。M4では「パスワード付きPDFは使えません」とわかりやすく表示し、M7でqpdfのWASM版などを追加する。pdf-libは2021年から更新が止まっている。
- **墨消し**：黒く塗った下の文字データも消す必要がある。pdf-libでは文字を部分的に消すのが難しいため、「墨消ししたページは画像にする」方式にする予定（そのページの文字は選択・検索できなくなる）。
- **結合で失われるもの**：pdf-libでページをコピーすると、しおり（目次）は引き継がれない。文書内リンクやフォームも正しく動かないことがある。M4で仕様として明記する。
- **OpenCV.jsのサイズ**：約8〜10MBある。四隅の検出だけなら自作の軽い処理で済む可能性があるので、M5で比べて決める。
- **iPhoneのPWAとカメラ**：ホーム画面から起動したPWAでは、カメラの許可を何度も聞かれることがある。実機で確認する。
- **アプリ内カメラの画質**：OSのカメラより落ちやすい。そのため「OSのカメラで撮る」も用意する。
- **画面テストのiPhoneはSafariではない**：この開発環境にはChromiumしかないため、iPhoneの画面サイズとタッチ操作をChromiumで再現している。Safari特有の動きは実機で確認する。
