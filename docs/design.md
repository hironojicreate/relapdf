# 設計の基本方針と決定事項

## 1. コンセプト

- **スマホ・タブレット（かんたんモード）**：撮った写真を3ステップでPDFに。「撮る/選ぶ → 確認・補正 → 保存/送る」
- **PC（詳細モード）**：結合・ページ整理・分割などの主要機能
- **共通**：ブラウザ内で完結する（ファイルを外部に送らない）。単一HTMLのPWAで、オフラインでも動く。一般公開できる構成にする

## 2. 設計原則

1. **ページリスト方式**
   読み込んだPDF・画像をすべて「ページの並び」として扱う。各ページは「元データ・回転・補正情報」を持つ。結合・並べ替え・削除・抽出・写真のPDF化を、すべて同じ仕組みで扱う。仕様は [page-list.md](page-list.md) を参照。
2. **Core層とUI層を分ける**
   ページリストの操作やPDF生成はCore（`src/core/`）、画面はUI（`index.html`）が担当する。CoreはDOMやブラウザ専用のAPIに触らず、Node.jsでテストできるようにする。
3. **状態は変更せず、新しく作る**
   Coreの操作は元の状態を書き換えず、新しい状態を返す。こうしておくと「元に戻す」機能や自動保存を作りやすい。
4. **状態とファイルの中身を分ける**
   ページリストはJSONに変換できる情報だけを持つ。PDFや写真の中身（バイナリ）は `sourceId` をキーにして別の場所（メモリやIndexedDB）に置く。
5. **重い処理は必要になったときだけ読み込む**
   自動四隅検出、日本語フォント、OCRなどは、その機能を使う画面を開いたときに読み込む。一度読み込んだらキャッシュし、オフラインでも使えるようにする。
6. **メモリを節約する**
   大きな写真は読み込むときに縮小し、1枚ずつ処理する（iPhoneのメモリ対策）。
7. **モード切替**
   画面の幅とタッチ端末かどうかで自動判定し、手動でも切り替えられるようにする。

## 3. 決定事項

| 項目 | 決定 | 理由・補足 |
|---|---|---|
| アプリ名 | **RelaPDF** | RelaVas・Relamemoとシリーズで名前をそろえる。「PDF」はISO規格の名前なので使ってよい |
| ライセンス | **MIT** | 誰でも自由に使えるが、作者名とライセンス文を残すことが条件。無保証 |
| ファイル構成 | `index.html` を本体とし、`sw.js`・manifest・アイコン・`vendor/`（ライブラリ）は別ファイル | Service Workerは別ファイルにしかできない。ライブラリを全部埋め込むと最初の読み込みが重くなる |
| ビルド | **なし**（ファイルをそのまま公開） | 構成を単純に保つ。CoreはES Modulesで書き、ブラウザとNodeの両方から読み込む |
| テスト | Core：Node標準の `node:test`。画面：Playwright（M1から） | 外部パッケージを増やさない |
| ライブラリの置き場所 | **リポジトリに同梱** | オフラインで動かすため。CDNは使わない |
| 公開先 | **Vercel**（GitHubリポジトリと連携して自動で公開） | アクセス数を見るため |
| アクセス解析 | **Vercel Web Analytics**（アクセス数がわかる程度） | Cookieを使わない。ファイルの中身は送らない |
| 外部との通信 | アクセス解析以外は行わない。CSPで制限する | Vercelのアクセス解析は同じドメインの `/_vercel/insights/` を使う |
| 対象端末 | iPhone（iOS 17以上）、Android（Chrome）、PC（Chrome/Edgeが中心、Safariも最低限動く） | 最新のPDF.jsは新しめのSafariを前提にしている |
| Androidの確認 | Playwrightで端末の画面サイズやタッチ操作を再現してテストする。公開前に可能なら実機で確認する | 開発者がAndroid端末を持っていない |
| カメラ撮影 | **最初からアプリ内カメラで連続撮影**。「OSのカメラで撮る」も用意する | OSのカメラは画質が良い。カメラの許可を拒否されたときの代わりにもなる |
| 向きの自動補正 | 写真の回転情報（EXIF）と、撮影したときの端末の向きに合わせる程度 | 書類の中身から向きを判定することはしない |
| 写真をPDFにするときの用紙 | 初期値は**A4**（縦横は写真に合わせて自動）。「写真のサイズのまま」も選べる | |
| 圧縮の目安 | 標準：A4で約150dpi相当／高画質：約300dpi相当 | |
| 作業途中の保存 | 作業中のページリストを端末内（IndexedDB）に自動保存し、再読み込みされても再開できる。履歴は持たない | iPhoneはカメラから戻ったときにページを再読み込みすることがある |
| UIの言語 | 日本語 | |
| ドキュメントとコメント | `docs/` に置く。コードのコメントは日本語 | リラメモの書き方にそろえる（未確認。[handover.md](handover.md) 参照） |
| リラメモ連携 | **今は作らない**。[roadmap.md](roadmap.md) の「今後の課題」に記録 | |

## 4. 使うライブラリ

MIT・Apache・OFL系に限り、AGPL系は使わない。どれもリポジトリの `vendor/` に同梱する。

| ライブラリ | 用途 | ライセンス | 使い始め |
|---|---|---|---|
| pdf-lib | PDFの生成・編集 | MIT | M1 |
| PDF.js | PDFの表示・画像化 | Apache 2.0 | M1 |
| fflate | 複数の画像をZIPにまとめる | MIT | M4 |
| OpenCV.js（または自作の軽い処理） | 四隅の自動検出 | Apache 2.0 | M5 |
| Noto Sans JP | 日本語フォント | OFL | M6 |
| qpdf（WASM版）など | パスワードの設定・解除 | Apache 2.0 | M7 |
| Tesseract.js | OCR | Apache 2.0 | M7 |

## 5. 注意しておく制約

- **pdf-libは暗号化に対応していない**：パスワード付きPDFは読み込めない。M4では「パスワード付きPDFは使えません」とわかりやすく表示し、M7でqpdfのWASM版などを追加する。pdf-libは2021年から更新が止まっている。
- **墨消し**：黒く塗った下の文字データも消す必要がある。pdf-libでは文字を部分的に消すのが難しいため、「墨消ししたページは画像にする」方式にする予定（そのページの文字は選択・検索できなくなる）。
- **結合で失われるもの**：pdf-libでページをコピーすると、しおり（目次）は引き継がれない。文書内リンクやフォームも正しく動かないことがある。M4で仕様として明記する。
- **OpenCV.jsのサイズ**：約8〜10MBある。四隅の検出だけなら自作の軽い処理で済む可能性があるので、M5で比べて決める。
- **iPhoneのPWAとカメラ**：ホーム画面から起動したPWAでは、カメラの許可を何度も聞かれることがある。実機で確認する。
- **アプリ内カメラの画質**：OSのカメラより落ちやすい。そのため「OSのカメラで撮る」も用意する。
