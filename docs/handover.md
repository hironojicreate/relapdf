### M5 自動検出＋書類モード（2026-10-21、v0.5.0）

- **ドラッグで落ちる場所の表示**（開発者の要望）：ドラッグ中、落ちる場所に太い線と「○番目へ」を出す。行の右端に落とすときは、次の行の左ではなくそのページの右に線を出す。位置が変わらない所では出さない。離したら動いたページが一瞬光り、「○番目に移動しました」と表示（`src/web/reorder.js` の `dropTargetAt`、`src/app/drag.js`）
- **詳細モードのタッチでのドラッグ**：ページを長押し（0.4秒）すると上下左右に動かせる。長押しの前に指が動いたらスクロールとみなす。かんたんモードのつまみは今までどおり押した瞬間から
- **カメラのズーム**：スライダーと2本指のピンチ。カメラ自体がズームできる端末（Androidの一部）はカメラのズーム、できない端末（iPhoneなど）は映像を拡大して、画面に見えている範囲だけを写真にする（最大4倍）。数字を押すと1倍に戻る（`src/web/zoom.js`）
- **四隅の自動検出**：`src/core/detect.js`（自作。数KB）、`src/web/detect-image.js`
  - 仕組み：長辺400pxに縮小 → 明るさだけにしてぼかす → 大津の方法で明るい所と暗い所に分ける → つながった大きなかたまり → 外形（凸包）にいちばん大きな四角形を当てはめる → かたまりとの重なりが85%以上、面積が写真の20〜98%、辺が写真の端に沿っていない、紙と背景の明るさの差が十分、のときだけ採用
  - 明るい紙（暗い机）と暗い紙（白い机）の両方を試す。紙が写真からはみ出している・紙が小さい・四角くない・机のムラだけ、のときは見つけない（今までどおり補正なし）
  - **撮影・写真の取り込み時に自動で4点補正をかける**。「自動で補正しました［補正を外す］」を6秒出す（カメラは閉じたときにまとめて「○枚を自動で補正しました」）
  - 補正画面：まだ補正していない写真は見つけた四隅から始める。「自動検出」ボタンでいつでも見つけた位置に戻せる（見つからないときはそう表示）
  - テスト用の写真（`document-photo.jpg`）では、四隅のずれは8px以内（1200×1600の写真）、検出にかかる時間は約60ms（開発環境のChromium）
  - **OpenCV.js との比較**：OpenCV.js は約8〜10MBあり、オフライン用に毎回キャッシュするには重い。今回の用途（机の上の紙）は自作の処理で十分に見つけられたので、OpenCV.js は使わないことにした。実機で見つからない写真が多ければ、改めて検討する（実機での比較はまだしていない）
- **書類モード**（背景を白く・文字をくっきり）：`src/core/color.js` の `applyDocumentFilter`
  - 仕組み：写真を小さなマスに分けて、マスごとに紙の白さ（明るい方から10%の明るさ）を調べ、まわりのマスで補ってなめらかにする → 各画素をその場所の紙の白さで割って白にそろえる（影や照明のムラが消える）→ 白と黒の幅を広げてくっきりさせる。色（赤い印鑑など）は残る
  - かける順番：4点補正 → 縮小 → 書類モード（`src/web/image.js` の `drawPage`。書き出し・サムネイル・大きなプレビュー・画像にする、のすべてで同じ）
  - **カメラ**：上部の「書類モード」ボタンでオン・オフ（最初はオン。端末に覚える：localStorage `relapdf:document-mode`）。オンのときに撮った写真に付く
  - **かんたんモードで写真を選んだとき**：書類が見つかった写真だけに付く（設定がオンのとき）。書類でない写真はそのまま
  - **補正画面**：「書類モード」のスイッチでページごとに切り替え
  - **詳細モード**：選んだ写真のページの「書類モード」ボタンで、まとめて切り替え（すべて書類モードなら外す）。詳細モードで読み込んだ写真には自動では付けない
- **テスト**：`npm test` 88件、`npm run test:e2e` 166件成功（5件は端末の種類で対象外）

### M4 詳細モード 第1段階（2026-10-18、v0.4.0）

- **複数ページの選択**：クリック／Shift+クリック（範囲）／Ctrl・⌘+クリック（追加・解除）、各ページ右上の丸（タッチ用）、「すべて選択」。Ctrl/⌘+A、Esc、ページ以外の場所のクリックで解除
- **一括操作**：選んだページの「回転」「削除」。Delete キーでも削除、Ctrl/⌘+Z で元に戻す。削除は1ページでも6秒間「元に戻す」を出す（かんたんモードのゴミ箱ボタンも同じ）
- **まとめてドラッグ**：選んだページのうち1枚をドラッグすると、選んだページをまとめて移動（つかんだページに「○ページ」と表示）。Core に `movePagesBefore` を追加
- **取り出す（抽出）**：`src/app/tools-dialog.js`。ページ範囲を入力（選んだページが最初から入る）して新しいPDFに。ファイル名は「元の名前_2-3.pdf」
- **分割**：「ページ範囲ごと（1-3, 4-6）」か「Nページずつ」。複数できたらZIP（「元の名前_分割.zip」）。Core に `parsePageRangeGroups`・`chunkPages` を追加
- **画像にする（PDF→画像）**：JPEG/PNG、150/300dpi。PDFのページは指定の解像度で、写真のページは補正・回転をかけて元の大きさで。複数ならZIP。`src/web/page-image.js`
- **大きなプレビュー**：ダブルクリックで開く。左右のボタン・矢印キーで前後へ、Esc で閉じる。`src/app/preview.js`
- **結合の注意**：PDFを読み込んでいるときだけ「PDFのしおり（目次）やリンクは引き継がれません」を書き出し欄に表示
- **同梱ライブラリ**：fflate 0.8.3（MIT、`vendor/fflate/`）
- **テスト**：`npm test` 73件、`npm run test:e2e` 138件成功（3件は端末の種類で対象外）

### 実機確認での修正（2026-10-18、v0.3.2）

開発者がiPhone実機で確認して見つかった点の修正。

- **4点補正の四隅が写真の端より外に動かせなかった**：仕様として写真の中（0〜1）に制限していた。横長の写真は画面の中央にしか表示されないため、画面の端まで動かせないように見えた。写真の外にも幅・高さの25%まで（画面の外には出ない範囲で）動かせるようにし、はみ出した部分は白で書き出す（`PERSPECTIVE_MARGIN`）
- **ルーペが写真の端で縦に伸びていた**：Safari は drawImage で画像の外にはみ出す範囲を指定すると、切り取らずに引き伸ばす（Chromium は切り取るので画面テストでは出なかった）。はみ出さない範囲を自分で計算して描くようにした（`src/web/canvas-util.js`）
- **カメラの明るさ調整**：撮影画面に明るさのスライダー（50%〜200%）を追加。プレビューに同じ明るさをかけ、撮った写真にも反映する。数字を押すと100%に戻る。設定は次回も覚えている（`src/core/color.js`、localStorage `relapdf:camera-brightness`）
  - 仕組み：カメラ自体の露出を変えるのではなく、撮った1コマの色に倍率をかけている（iPhoneのSafariはカメラの露出調整に対応していないため）。白くなりすぎた部分は白のまま

### 自動アップデートとホーム画面への追加（2026-10-18、v0.3.1）

- **自動アップデート**：`src/web/updater.js`。起動時・アプリに戻ったとき・1時間ごとに新しいバージョンを確かめ、裏で取り込む
  - 作業中でなければ、すぐに新しいバージョンに切り替える（作業を保存してから読み込み直す）
  - 作業中は「新しいバージョンがあります［更新する］」を出す。ほかのアプリに切り替えている間に自動で切り替える
  - カメラ・補正画面・ダイアログ・処理中は切り替えない
  - 切り替わったら「最新版（vX）に更新しました」と表示する
  - 仕組み：公開したファイルが1つでも変わると `precache-manifest.js` のバージョンが変わる → ブラウザが新しい Service Worker を見つける → 全ファイルを取り込んで待機 → `skip-waiting` で切り替え → ページを読み込み直す
- **ホーム画面への追加の案内**：`src/web/install.js`。最初の画面に「ホーム画面に追加して、アプリとして使う」を出す。Android・PCのChrome/Edgeはインストール画面、iPhone/iPadは手順のダイアログ。ホーム画面から開いているときは出さない
- **テスト**：テスト用サーバー（`tests/e2e/server.js`）を、テストの中から別のポートで立てて中身を差し替えられるようにし、「新しいバージョンを公開した」状態を再現している。`npm test` 62件、`npm run test:e2e` 86件成功（1件はPCでは対象外）

### M1 土台（2026-10-18）

- **PDFの書き出し**（Core）：`src/core/pdf-export.js`。PDF・写真・白紙を並びの順番で1つのPDFにする。PDFのページは画像にせずそのままコピーし、もともとの回転にユーザーの回転を足す。パスワード付きPDFや壊れたPDFは、わかりやすいエラーにする
- **用紙への配置と画質の計算**（Core）：`src/core/layout.js`。A4に収める／写真のサイズのまま、標準150dpi／高画質300dpi
- **ファイル名**（Core）：`src/core/filename.js`。初期値は `RelaPDF_日付_時刻`、使えない文字の置き換え
- **ブラウザ側の部品**（`src/web/`）
  - `image.js`：写真の読み込み（回転情報を反映し、長辺3508pxまで縮小してJPEGで保持）、書き出し用の縮小、サムネイル
  - `pdf-view.js`：PDF.js を必要になったときに読み込み、サムネイルを作る
  - `save.js`：ダウンロードと共有シート
  - `source-store.js`：元データの置き場所（今はメモリ。M2でIndexedDBにする）
  - `mode.js`：かんたん／詳細モードの自動判定と、手動で選んだモードの記憶
- **画面**：`index.html`（骨組みとCSS、ダークモード対応）と `src/app/main.js`（動き）
  - かんたんモード：「カメラで撮る」「写真を選ぶ」→ ページ一覧 → PDFを作成
  - 詳細モード：ファイルを選ぶ／ドラッグ＆ドロップ → ページ一覧 → PDFを作成
  - 各ページで、前へ・後ろへの移動、回転、削除ができる
  - PDFを作ったあとに「送る・保存する」（共有シートが使える端末だけ）と「ダウンロード」を出す
  - 作業中にページを閉じようとすると確認する（M2で自動保存に置き換えて削除）
- **PWA**：`manifest.webmanifest`、`sw.js`（全ファイルを最初にキャッシュ）、`precache-manifest.js`（`scripts/precache.js` で自動生成）、アイコン（`icons/`、仮のデザイン）
- **CSP**：`index.html` の meta で外部への接続を禁止している
- **同梱ライブラリ**：`vendor/`（pdf-lib 1.17.1、PDF.js 6.4.299 legacy版）。詳細は `vendor/README.md`
- **テスト**
  - `npm test`：Core・モード判定・キャッシュ一覧の確認、44件すべて成功
  - `npm run test:e2e`：Playwright で PC・Android（Pixel 7）・iPhone（iPhone 15 の画面サイズ）を再現し、8項目×3端末＝24件すべて成功

## 注意点・未解決

- **バージョン**：今は 0.5.0。段階を終えるごとに上げる（M3 なら 0.3.0、小さな修正は 0.2.1 のように）。`src/app/version.js` と `package.json` の両方を変えて、`npm run precache` を実行する

- **リラメモの書き方にそろえる件**：開発者からは「そろえてよい」「あとで」と了承済み。M0のセッションでは、リラメモのリポジトリ（private）を読む権限がなかったため、まだ確認していない
- **画面テストのiPhoneはSafariではない**：この開発環境にはChromiumしかない。Safari特有の動き（共有シート、HEIC写真、カメラの許可）は実機で確認する
- **日本語のファイル名のダウンロード**：文字コードの設定がない環境のChromiumでは「download」という名前になる。テストでは `playwright.config.js` で `LANG=C.UTF-8` を指定して回避している（利用者のブラウザには関係ない）
- **キャッシュ一覧**：アプリのファイルを変えたら `npm run precache`。忘れると `npm test` が失敗して知らせる
- **Service Worker の更新**：v0.3.1 から自動で切り替わる（上記）。v0.3.0 以前を開いている端末は、一度アプリを全部閉じて開き直すと v0.3.1 になり、以後は自動で更新される
- **iPhoneのホーム画面のアプリ**：Safari とは保存領域が別なので、Safari で作業中のページはホーム画面のアプリに引き継がれない（案内のダイアログにも書いてある）
- **4点補正の引き伸ばし・書類モード**：今は画面と同じスレッドで計算している。iPhoneで遅ければ Web Worker に移す
- **四隅の自動検出の限界**：紙と背景の明るさの差で見つけているので、白い机の上の白い紙や、柄の多い机では見つからないことがある。そのときは今までどおり手で合わせる
- **書類モードの限界**：写真や図の多いページでは、明るい部分が白く飛ぶことがある。そのページは書類モードを外す
- **アプリ内カメラの画質**：今は映像の1コマを使っている。Android の Chrome などでは ImageCapture の `takePhoto()` でより高画質に撮れる可能性があるが、実機で確かめられないため見送った（今後の課題）
- **カメラのライト（トーチ）**：未対応（今後の課題）
- **カメラの露出**：Android の Chrome では `exposureCompensation` でカメラ自体の露出を変えられる可能性がある（今は全端末で色の倍率で調整）。今後の課題
- **Safari と Chromium の違い**：canvas の drawImage のように、Safari だけで起きる描画の違いがある。画面テストは Chromium なので、描画まわりは実機で確認する
- **画面テストのカメラ**：Chromium のテスト用の映像（緑の画面）を使っている。`playwright.config.js` の起動オプションで指定
- pdf-libの制約（暗号化に非対応、しおりが引き継がれない）は [design.md](design.md) の「注意しておく制約」を参照
- 保存先の名前（IndexedDBのデータベース名、localStorageのキー、キャッシュ名）には `relapdf` を付ける（将来のリラメモ連携に備える）。今使っているのは localStorage の `relapdf:mode`・`relapdf:camera-brightness`・`relapdf:document-mode`、IndexedDB の `relapdf`（`sources`・`state`）、キャッシュ名 `relapdf-<バージョン>`
